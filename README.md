# Голосовой помощник для учебной консультации

Учебный браузерный голосовой помощник для проверки вымышленного расписания и создания локальных демонстрационных записей. Приложение распознаёт завершённую голосовую реплику, передаёт текст AI-агенту и постепенно показывает ответ. Синтезированную речь воспроизводит функция Speech Synthesis браузера.

**Реальная запись не создаётся.** После проверки слота имя клиента и время можно явно подтвердить в форме; демонстрационная запись сохраняется в локальном файле `data/demo-bookings.json` и появляется в списке приложения. Google Calendar и Google Sheets пока не подключены. Демо-расписание: завтра 18:30 свободно, завтра 19:00 занято, на послезавтра данных нет.

## Этапы проекта

- **Lite:** схема и сценарий без кода подготовлены и сверены с требованиями задания в [docs/lite-flow.md](docs/lite-flow.md).
- **Pro:** реализовано браузерное приложение с записью реплики, распознаванием, проверкой расписания, локальным списком демонстрационных записей, потоковым текстом, голосовым ответом и состояниями сессии.

## Требования

- Node.js 22 или новее.
- API-ключ OpenAI для распознавания речи и работы AI-агента. Звуковое воспроизведение выполняется браузером и не отправляет текст ответа отдельному TTS-сервису.
- Современный браузер с поддержкой `MediaRecorder`, `getUserMedia`, `fetch` streaming и `speechSynthesis`.

## Настройка и запуск

API-ключ хранится в `.env.local` в корне проекта. Этот файл исключён из Git. Для отдельной машины:

1. Скопируйте `.env.example` в `.env.local`.
2. Заполните `OPENAI_API_KEY` своим ключом. Не добавляйте ключ в браузерный код и не публикуйте `.env.local`.
3. Выполните `npm start`.
4. Откройте `http://localhost:3000` и разрешите доступ к микрофону при первом запросе записи.

Если приложение показывает `PROVIDER_CONNECTION_FAILED`, процесс Node.js не может подключиться к OpenAI API. В некоторых ограниченных средах Codex исходящие соединения блокируются. Запустите сервер из обычного PowerShell вне такой среды:

```powershell
Set-Location "E:\Univer_AI\Разработка AI-агентов на Codex\Тема 8. Голосовые AI-агенты STT, TTS и Realtime-общение"
npm start
```

Если порт 3000 занят, задайте свободный порт перед запуском, например `$env:PORT = '3003'`, и откройте соответствующий адрес `http://localhost:3003`.

В проекте нет внешних npm-зависимостей. Для использования уже настроенного в этой рабочей папке ключа достаточно выполнить `npm start`.

Не начинайте разговор с чувствительными сведениями: аудио реплики отправляется в OpenAI для распознавания, а расшифровка и ограниченный контекст диалога — для формирования ответа. Сервер не сохраняет аудио и не пишет содержимое реплик или ключ в журналы.

## Демонстрация

1. Нажмите «Начать разговор».
2. Нажмите «Начать запись реплики», спросите «Можно завтра после шести?» и остановите запись.
3. Проверьте расшифровку, постепенное появление ответа, результат в расписании и голосовое воспроизведение. Ожидаемый ответ предлагает 18:30 и сообщает, что 19:00 занято.
4. В форме «Записать клиента» укажите имя, выберите свободный слот и установите флажок подтверждения. Запись появится в списке и сохранится локально на сервере. Имя из формы не отправляется AI-сервису.
5. Спросите про послезавтра: помощник должен сказать, что данных нет и подтвердить доступность нельзя.
6. Для перебивания нажмите запись во время озвучивания: старый звук останавливается, незавершённый ответ отменяется, новая реплика обрабатывается.
7. Завершите разговор. Начало следующего разговора очищает историю предыдущей сессии.

## Архитектура и поток

Каскад: браузерная запись → серверный `gpt-transcribe` для STT → Responses API с ограниченным вызовом `check_schedule` → поток текста по SSE → голосовое воспроизведение через `speechSynthesis` браузера. Демонстрационные записи сохраняются только на локальном сервере. Поток реализован для текста ответа. Входящее аудио передаётся после остановки записи; оно не поступает как живой аудиопоток. Голос браузера не является потоковым ответом из TTS API.

В исходном плане указан серверный TTS. В этой реализации выбрана встроенная речь браузера: актуальная документация OpenAI помечает модели `/v1/audio/speech` как устаревающие с отключением 6 января 2027 года и направляет миграцию к Realtime, а Realtime исключён требованиями проекта. Поэтому здесь сохраняется каскад без зависимости от скоро отключаемого TTS API. Озвучивание зависит от русских голосов, доступных на устройстве.

Тестовый инструмент расписания детерминирован, читает локальную фикстуру с датами относительно «завтра» и «послезавтра» и не имеет операции создания записи. Ошибки провайдера, отсутствие данных и просьба уточнить дату представлены разными состояниями.

## Описание конфигурации

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Секретный серверный ключ для STT и Responses API | Не задана |
| `OPENAI_TEXT_MODEL` | Модель, которая разбирает запрос и формулирует ответ | `gpt-6-luna` |
| `OPENAI_TRANSCRIBE_MODEL` | Модель распознавания записи | `gpt-transcribe` |
| `PORT` | Порт локального HTTP-сервера | `3000` |
| `APP_ACCESS_PASSWORD` | Пароль доступа к приложению; обязателен при `NODE_ENV=production` | Не задана локально |
| `BOOKINGS_PATH` | Полный путь к JSON-файлу демонстрационных записей | `data/demo-bookings.json` в папке проекта |

Когда задан `APP_ACCESS_PASSWORD`, браузер запрашивает доступ к приложению. Для публикации задайте в панели хостинга `NODE_ENV=production`, `APP_ACCESS_PASSWORD` и `OPENAI_API_KEY`; используйте длинный уникальный пароль. Сервер отвечает только после проверки пароля, а ключ OpenAI остаётся на сервере.

## Развертывание на Hostinger

В Hostinger Business/Cloud создайте сайт типа **Web App**, подключите приватный репозиторий GitHub, выберите Node.js 22 и preset **Other**. Для этого проекта файл точки входа — `server.mjs`; этап сборки не требуется, зависимости npm не используются. Установите `NODE_ENV=production`, `APP_ACCESS_PASSWORD` и `OPENAI_API_KEY` в Environment variables, затем выполните Deploy. Приложение слушает порт `PORT` и сетевой интерфейс `0.0.0.0`.

Демо-записи хранятся в локальном JSON-файле. На управляемом Node.js хостинге Hostinger каждое развёртывание получает отдельный каталог версии, поэтому локальный файл не следует считать постоянной базой данных. Для долговременного хранения используйте внешний database provider или Hostinger VPS с отдельным постоянным путём и задайте его через `BOOKINGS_PATH`.

## Ограничения

- Данные расписания и записи вымышленные и используются только для учебной демонстрации.
- Приложение не подключено к Google Calendar или Google Sheets; локальная демонстрационная запись не является реальной записью на консультацию.
- Входящая реплика записывается целиком и отправляется после остановки записи. Это каскадная обработка, а не Realtime-сессия.
- Синтез речи зависит от голосов, установленных в браузере/операционной системе.
- Не выполнены голосовые вызовы к API из этой среды; для полной демонстрации пользователь запускает приложение и разрешает микрофон в браузере.
